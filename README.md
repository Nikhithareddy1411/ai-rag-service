# AI RAG Service

Production-oriented Retrieval-Augmented Generation API built with FastAPI. This increment adds a free local Sentence Transformer embedding model on top of PostgreSQL + pgvector persistence.

## Architecture

```text
Client
  |
  v
FastAPI
  |-- JWT Authentication
  |-- Document Ingestion -> Chunking -> Local Transformer Embeddings
  |                         |                    |
  |                         |                    v
  |                         |             all-MiniLM-L6-v2
  |                         v
  |                    PostgreSQL + pgvector
  |
  `-- Search -> Transformer Query Embedding -> cosine similarity -> Top-K chunks
```

## Embeddings

The service uses `sentence-transformers/all-MiniLM-L6-v2` by default. It is an open-source Apache-2.0 model that maps text to 384-dimensional vectors and is intended for semantic search and sentence similarity. The model runs locally after its first download; no hosted embedding API is required. citeturn0search0turn0search5

Sentence Transformers provides the model through the `sentence-transformers` Python package and returns 384-dimensional embeddings for this model. citeturn0search1turn0search9

The provider normalizes embeddings before storing/searching them, so pgvector cosine similarity can use normalized dot-product behavior efficiently.

### Model configuration

```env
EMBEDDING_MODEL_NAME=sentence-transformers/all-MiniLM-L6-v2
EMBEDDING_DIMENSION=384
```

If the configured dimension does not match the loaded model, startup/use fails with an explicit dimension mismatch instead of silently corrupting the vector store.

## Persistence

- PostgreSQL is the system of record for documents and chunks.
- pgvector stores 384-dimensional embeddings using the `vector` type.
- SQLAlchemy 2.x provides ORM models and sessions.
- Alembic manages schema migrations.
- An HNSW index uses cosine distance for scalable nearest-neighbor search.
- `DocumentRepository` isolates persistence from the FastAPI routes.
- `InMemoryDocumentRepository` remains available for fast unit/API tests.

## Database Setup

The included Compose stack starts `pgvector/pgvector:pg16`, creates the database, waits for PostgreSQL health, then runs `alembic upgrade head` before starting FastAPI.

```bash
docker compose up --build
```

The database is persisted in the `postgres_data` Docker volume.

For local Python execution, configure:

```bash
DATABASE_URL=postgresql+psycopg://rag:rag@localhost:5432/ragdb
```

Run migrations manually with:

```bash
alembic upgrade head
```

Rollback the latest migration with:

```bash
alembic downgrade -1
```

## API

```http
GET  /health
GET  /ready
POST /api/v1/auth/token
POST /api/v1/documents
POST /api/v1/search
```

`/api/v1/documents` and `/api/v1/search` require a bearer JWT.

### Ingest a document

```bash
curl -X POST http://localhost:8000/api/v1/documents \
  -H "Authorization: Bearer $TOKEN" \
  -F "file=@policy.txt"
```

### Search

```bash
curl -X POST http://localhost:8000/api/v1/search \
  -H "Authorization: Bearer $TOKEN" \
  -H 'Content-Type: application/json' \
  -d '{"question":"What is the compliance reporting process?","top_k":5}'
```

Search now executes cosine-distance retrieval directly in PostgreSQL using vectors generated by the local transformer model.

## Tests

```bash
pytest -q
```

Embedding unit tests use a small fake model so the normal test suite does not need to download the transformer model. They verify vector dimensionality, normalization, batch encoding, and configuration/model dimension validation. The PostgreSQL integration test runs when `TEST_DATABASE_URL` is set.

For an end-to-end local test with the actual model and database:

```bash
docker compose up --build
pytest -q
```

The first model use downloads the pretrained model from Hugging Face; subsequent runs use the local model cache.
